## 一、当前项目目标

先完成角色选择页 UI，再制作五名角色的出场动画并接入页面。

该页面不是独立角色模型站在统一背景中的展示页。五张角色美宣本身将发展为五段全屏角色出场动画；玩家切换或选中角色时，完整场景、人物、镜头和动作一起播放。UI 只覆盖在动画边缘，不能遮挡美宣的核心叙事。

游戏不是 MOBA、多人竞技、抽卡或重度角色养成游戏。玩法包括：

- 音乐节奏玩法。
- 横屏跑酷玩法。
- 未来可能继续扩展《星谱大陆》下的其他模式。

UI 必须同时服务多种玩法，不能被设计成只适合音乐、跑酷或战斗中的某一种功能皮肤。

## 三、角色选择逻辑已经确认

- 单角色选择，不是多人组队。
- 五张角色卡横向排列，点击任意卡片直接切换到对应角色。
- 画面左右各有一个切换箭头，可按固定顺序前后切换。
- 固定顺序：`MILUKA → NAISHA → PEKO → YANQIU → BOMU`。
- 当前选中的角色卡轻微放大并上移，未选中卡仍保持清楚。
- 点击确认按钮后选定当前角色。
- 当前按钮文字只使用 `CONFIRM`，不使用 `SELECT MILUKA` 等带角色名的长文案。
- 页面所有可见文字当前统一使用英文，不使用中文。

## 四、页面布局已经确认

16:9 全屏角色动画是第一视觉中心。UI 固定在边缘：

- 左上：返回按钮。
- 左侧：角色名、身份、一句话介绍、三个特性。
- 左右边缘中部：前后切换箭头。
- 中间靠下：五张小型角色卡。
- 右下：`CONFIRM`。
- 右上：金币与宝石两种货币。

五张卡不能贴底，也不能占满下半屏。当前目标比例约为 `3:4`，而不是此前高窄的 `2:3`。以 1920×1080 为基准，单卡可从约 `116–124 × 150–164 px` 起步，卡间距约 `12–16 px`，最终尺寸需在 Figma 中结合动画安全区验证。

游戏画面所说的“出血”实际执行为 UI 安全区：

- 左右至少 `96 px`。
- 上下至少 `54 px`。
- 背景美宣继续铺满画面；所有可交互 UI、文字、描边和装饰完整落在安全区内。

## 六、货币系统

右上角只放两种货币：

- 金币：示例值 `12,580`。
- 宝石：示例值 `680`。

每种货币右侧可有独立小型 `＋` 按钮。暂不增加体力、第三货币、头像、邮箱、商城、通知或任务入口。

货币框不能是普通输入框或毫无性格的胶囊条，但也不能使用大量尖角。目标是圆润、略带向右前进动势的“流动星谱胶囊”：

- 左侧货币图标形成稍大的圆形、水滴形或种荚节点。
- 中部承载动态数值。
- 右侧加号区可形成圆钝花瓣。
- 动势来自曲线、节点大小与轻微错位，而不是刀刃尖角。
- 框体需要考虑九宫格切片或固定尺寸资产＋程序文字叠加。

宝石已明确使用短小、中央略宽、圆钝的青蓝晶体，不使用细长冰锥式宝石。参考：`reference-rounded-gem.png`。

## 七、UI 与美宣需要统一什么

美宣和 UI 不需要使用相同绘制方式。美宣负责故事、角色表演、电影镜头和复杂光影；UI 负责操作与信息秩序。

必须共享：

- 品牌色彩关系。
- 圆润亲和的形状性格。
- 星谱、轨迹、星象仪、冒险路径等符号。
- 统一的图标、字体与动效节奏。

不必共享：

- 美宣的厚涂笔触。
- 场景复杂光照。
- 大范围魔法粒子。
- 每张美宣的具体环境与主色。

结论：UI 要像来自同一个世界，不必与美宣使用同一种材质。

## 八、最终视觉方向

当前暂定名称：**圆润星谱器物 UI**。

它不是纯扁平企业 UI，也不是传统重度奇幻 RPG 金框，更不是满屏尖角的竞技 HUD。形状比例：

- 约 70% 圆润柔和轮廓。
- 约 20% 流动曲线。
- 约 10% 星形或方向性重音。

世界观可借用：种荚、花瓣、水滴、魔法瓶、圆钝星章、流动谱线、旅行铭牌和小型星象仪器。

关键纠正：圆润不等于普通圆角矩形。组件必须有一个清楚的非标准记忆点，但不能在每一条边上反复凹凸，也不能用尖锐指针收尾。

### 当前最有价值的参考取舍

- 布局：使用已归档 `ui-iteration-02-immersive-layout.png` 的沉浸式全屏动画＋边缘 UI 关系。
- Icon：采用今晚参考中“深色底形＋清楚彩色主体”的扁平图标逻辑。
- 精度：借鉴精致奇幻 UI 的双层边线、曲线控制和统一工艺，但不继承厚重面板与大面积金框。
- 资产关系：风格化表皮可以由设计师绘制并切成 PNG；开发负责布局、点击区域、状态切换和动态文字。

## 九、配色系统

今晚确认不能让整套 UI 都跟随米露卡变成紫色。紫色过量同时来自米露卡垫图和此前提示词反复指定“深靛蓝至紫罗兰”。

正确方案：**固定中性品牌骨架＋少量角色主题色**。

通用色建议：

- 主表面：中性蓝黑／炭灰蓝，如 `#18202B`、`#202938`。
- 次级表面：低饱和灰蓝，如 `#2D3948`。
- 主文字：暖象牙白，如 `#F3EBD8`。
- 次文字：雾灰蓝，如 `#AEB9C7`。
- 品牌细边：低饱和古金，如 `#B99A62`。

角色强调色只占 UI 约 10%–15%，用于选中卡内边、角色身份、小徽章、特性 Icon 少量区域和确认按钮的细小状态标记：

- 米露卡：青绿。
- 奈纱：冰蓝。
- 佩可：暖橙。
- 砚秋：柔金或低饱和紫。
- 波姆：月白蓝。

返回、箭头、货币、未选中卡、正文和确认按钮主体均保持中性品牌色。金币固定暖金，宝石固定青蓝。

## 十、资产与开发关系已经纠正

今晚曾错误地把“方便开发”理解为所有组件都必须能由 Figma 基础矢量或程序样式直接复刻。这导致 UI 退化成普通圆角矩形、圆章和胶囊条。

正确协作方式：

- 设计师可以绘制异形按钮、卡框、箭头、货币框和 Icon。
- 固定组件可以切透明 PNG。
- 可伸缩框体可使用九宫格切片。
- 动态数值与文字由程序叠加。
- 默认、悬停、选中、按下、禁用可提供不同资产或由程序叠加反馈。
- 外观图标可以异形，但点击区域仍使用不小于约 48×48 px 的透明矩形。

允许组件轮廓内部使用渐变、材质、微光、星点和高光。当前禁止的是超出组件边界的大范围柔光、散射粒子、长能量尾迹和无法确定切图边界的效果。后期交互阶段可以另外加入外围光效。

## 十一、今晚的四个关键迭代

均已归档在 `assets/handoff/2026-08-27/character-select/`。

### 1. `ui-iteration-01-ornate-large-cards.png`

优点：整体精致、Icon 和深蓝金色氛围有吸引力。

问题：卡片过大，按钮过重，光效过多，接近成品宣传图，遮挡角色动画；整体偏传统华丽手游。

### 2. `ui-iteration-02-immersive-layout.png`

目前最值得保留的页面关系：动画是第一主体，左侧无大底板信息，底部五卡，左右箭头，右下确认。它是布局参考，不是最终组件风格。

### 3. `ui-iteration-03-overornate-narrow-cards.png`

优点：组件开始有独立绘制感，宝石、箭头、卡框和按钮形成了较强风格化方向。

问题：卡片太高太窄；轮廓弯绕、底部尖锐；特性 Icon 过度复杂；确认文案过长；UI 安全区不足；货币框和整体仍受米露卡紫色污染。

### 4. `ui-iteration-04-generic-rounded-regression.png`

已明确判定为退步，不作为视觉母版。

它完成了安全区、圆钝宝石、扁平 Icon、宽卡和 `CONFIRM` 等功能纠正，但模型把“圆润、简洁、统一、不要弯绕和不要尖角”平均执行为普通圆角矩形、圆形徽章和胶囊条，彻底失去品牌辨识度。

该图只可参考尺寸、安全区和信息层级，不能继续作为视觉样式母版。

## 十二、已确认的生成陷阱

1. **在完整美宣上同时重做全部 UI，模型会优先保护背景与角色，UI 退回通用模板。**
2. **大量“不要尖角、不要弯绕、保持圆润、保持统一”的限制会被平均成普通圆角矩形。**
3. **只说“风格化”不指定具体造型隐喻，模型会用金框、光效和复杂花纹假装风格化。**
4. **米露卡美宣会把整套 UI 污染成紫色；提示词再强调紫罗兰会加重问题。**
5. **角色卡同时追求小、竖、容纳半身像和复杂边框，容易变成高窄塔牌。**
6. **要求所有组件纯矢量可复刻，会无意中抹掉设计师可切 PNG 的绘制资产空间。**
7. **一次长提示词同时修改背景保护、布局、组件造型、Icon、配色、文字和状态，结果常常只修正功能，不产生高质量造型。**

连续全图迭代已经出现“更正确但更普通”的回归，下一次公司端会话不要继续在完整页面上叠加长提示词。

## 十三、下一步已经确定：先做独立 UI 资产板

下一次公司端会话暂时不垫角色美宣，不直接生成完整页面。

先在完全均匀的浅暖灰背景（建议约 `#E8E5DF`）上生成独立 UI 资产设计板。浅暖灰比纯白更容易看清象牙白、浅金高光和深色边缘，同时仍方便抠图。

推荐将资产板分成 A、B、C 三列，每列是一整套内部一致的组件家族，而不是把十几个互不相关的按钮混在一起：

- A：圆润星象仪器。
- B：圆润旅行铭牌。
- C：圆润乐器／星谱器物。

每列包含：

- 一张代表性角色卡框。
- 一个 `CONFIRM` 按钮。
- 一个金币框。
- 一个宝石框。
- 一个返回按钮。
- 左右箭头。
- 三个特性 Icon。

资产板要求：

- 正面视图，无透视。
- 无角色、无场景、无手、无桌面、无展示架。
- 各资产互不接触。
- 背景颜色完全均匀。
- 外围没有光效与粒子。
- 内部允许渐变、材质、微光和高光。
- 不生成最终页面布局。

先选择一个完整组件家族，再单独放大生成并人工精修，之后切 PNG，最后贴回至少米露卡与佩可两张冷暖差异最大的美宣验证适配。不要只在米露卡上验收。

## 十四、下一次公司端会话的执行顺序

1. 先读本文，不继续加载动画。
2. 打开已归档四张 UI 迭代，明确视觉母版与失败边界。
3. 以独立浅暖灰资产板探索 A/B/C 三套组件家族。
4. 只比较轮廓辨识度、圆润程度、组件家族一致性、切图边界和冷暖背景适配性。
5. 选定一套后，单独生成或绘制角色卡、确认按钮、货币框、返回与箭头。
6. 在 Figma 中建立 1920×1080 页面、安全区、栅格与组件占位。
7. 将通过的 PNG 资产置入 Figma，程序文字和动态数值分离。
8. 先用米露卡与佩可美宣做冷暖双场景验证。
9. 页面 UI 通过后，再制作／接入五名角色出场动画。
