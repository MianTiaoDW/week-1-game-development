## 三、2026-08-28 最高层变化

### 已确认：主玩法选择 B

游戏不再以纯节奏玩法作为主循环。用户已选择：

> **B：有起点终点、岔路、剧情事件和探索收集的关卡制横版冒险跑酷。**

节奏游戏保留，但降为世界中的小游戏或特殊玩法，不再要求整款游戏围绕连续音符判定搭建。

这项选择比当前角色选择页 UI 更高一层。接下来必须先把首版跑酷闭环锁清楚，再决定营地、地图、角色选择、关卡 HUD、结算和节奏小游戏分别需要哪些 UI。

### 方向已确认，细节未锁

- 关卡为横版、关卡制，不是《地铁跑酷》式无限刷分。
- 每关应有明确起点、终点和可重复挑战价值。
- 关卡可以包含岔路、探索收集与小型叙事事件。
- 五名角色应当通过动作能力和冒险身份产生差异，而不是强行对应五种乐器。
- 节奏玩法作为营地活动、庆典、遗迹共鸣、角色事件或特殊关卡存在。
- 历史目标“单局约 2–3 分钟、简单好玩、可重复挑战”仍适合作为首版约束，但需在下一轮重新确认。

### 尚未核验

- 玩家是否自动前进。
- 输入设备优先级：键鼠、手柄、移动触屏，或同时支持。
- 基础输入是否为跳跃／滑行／冲刺，是否允许方向控制。
- 失败条件：碰撞次数、生命值、掉落、时间，或检查点。
- 岔路是实时操作选择、能力门槛，还是关前路线选择。
- 五名角色的能力差异是否影响路线、战斗、收集或评分。
- 是否存在轻战斗、追逐、Boss 或纯障碍跑酷。
- 长期成长是解锁路线与故事，还是包含轻量装备／技能；当前禁止默认扩成重养成。
- 首发平台、画面方向与性能预算需要重新确认。当前角色选择原型仍按 16:9 横屏处理。

## 四、首版跑酷闭环候选

以下是当前最小、最贴合现有资产的候选，不是已经批准的完整玩法：

```text
营地／旅团据点
→ 选择同行者
→ 选择一条星路关卡
→ 进入 2–3 分钟横版冒险跑酷
→ 跨越障碍、收集星谱碎片、选择上下岔路
→ 抵达终点或触发小型事件
→ 结算路线、收集与共鸣表现
→ 返回营地，解锁下一条路线或角色档案
```

候选基础动作：跳跃、滑行、短冲刺、一个角色能力。不要在第一版同时加入攻击连招、装备切换、宠物、多人联机、复杂技能树和抽卡养成。

### 音乐如何保留

已确认：节奏游戏作为小游戏加入世界。

可以继续验证但尚未锁定：

- 普通跑酷关卡中的障碍、镜头和收集物按音乐段落组织，但不要求玩家全程打拍子。
- 在合适节奏点跳跃或冲刺，可获得“星谱共鸣”奖励；错过也能通关。
- 营地庆典、遗迹机关或角色事件可进入完整节奏小游戏。
- 高级挑战可把节拍命中变成隐藏路线或高评价条件，而不是基础通关门槛。

这能保留《星谱大陆》的“星谱”世界规则，同时避免把游戏重新锁死成纯音游。

## 五、为什么跑酷方向适合现有项目

- 五名角色已经拥有清楚的动作性格、装备与冒险身份，可以自然转化为移动能力。
- 横版美宣、草地、悬崖、道路、甲虫和小队旅行素材可以继续服务关卡氛围、加载动画和章节演出。
- 已规划的加载动画本来就是从草丛、队伍行进到世界揭示，天然支持“出发旅行”的主循环。
- 角色选择页仍然有价值，但它从独立展示页变成“选择本次同行者／出发角色”的入口。
- 跑酷主循环能继续容纳音乐、收集、探索、剧情和小游戏，不需要废弃《星谱大陆》的命名与世界观。

## 六、UI 最新审美结论

### 已确认的用户偏好

用户目前最喜欢的是类似《出发吧麦芬》分析图所呈现的整体 UI 方法：

- 温暖、清新、治愈的奇幻冒险气质。
- 奶油黄／暖象牙白内容区。
- 清浅蓝结构边框与标题条。
- 暖橙主操作按钮。
- 少量薄荷绿作为完成、可领取和安全状态。
- 圆润、亲和、信息清楚，但不是充气玩具式 2.5D。
- 角色与场景负责鲜艳，UI 负责稳定、温暖与易读。
- UI 有完整系统，而不是每个页面为当前美宣单独换皮。

当前暂定名称：

> **温暖星路旅行 UI**

其核心不是复制烘焙、猫咪、遮阳篷或活动商城，而是把同样的系统方法翻译成《星谱大陆》的星图、旅册、道路、行李标签、地图折线与同行者旅签。

### 一个关键纠正

用户并非绝对讨厌奶油色面板。此前不满意的是“大块白板直接压住角色美宣、缺乏系统、只适配米露卡”。

- 在背包、任务、角色档案、设置、关卡地图等功能型页面，可以使用完整奶油色旅行册面板。
- 在角色选择、章节开场、剧情、关卡和结算等沉浸式页面，只使用边缘小组件、文字、旅签和必要的可读性遮罩，不能用大面板切断美宣。

## 七、UI 两类页面

### A. 沉浸式页面

适用：角色选择、章节开场、剧情演出、跑酷关卡、结算。

- 美宣、场景或实时游戏画面是第一视觉中心。
- UI 位于边缘，面积小、层级清楚。
- 角色名可以直接排版，背后只允许无边界的程序化渐变遮罩。
- 同行者旅签、状态徽记和主按钮使用奶油底、浅蓝结构边与少量角色色。
- 不放完整奶油白菜单板。

### B. 功能型页面

适用：营地主页、关卡地图、背包、任务、角色档案、设置、收集册。

- 可以使用完整的奶油色旅行手册面板。
- 浅蓝标题条统一页面层级。
- 暖橙用于主要行动，薄荷绿用于完成与领取。
- 背景可以是模糊营地、纸张地图或轻场景，不必每页使用角色美宣。
- 第一版只建立跑酷闭环需要的页面，禁止照着参考图补齐商城、抽卡、战令、月卡、时装和复杂社交。

## 八、当前角色选择页结构

### 已确认的概念

角色选择页仍采用“全屏角色美宣／未来角色出场动画＋边缘 UI”。美宣只负责角色表演与场景，不决定 UI 配色。

用户已画出位置与大致尺寸原型：

`assets/handoff/2026-08-28/ui-and-runner/character-select-layout-prototype.png`

原型结构：

- 左上：返回。
- 左侧：角色名、身份／介绍、三个特性图标。
- 左右中部：切换箭头。
- 右上：金币与宝石。
- 底部中央：五张小型角色卡／同行者旅签。
- 右下：确认选择。

位置和相对大小已经由用户确定到可继续设计的程度，但尚未在 Figma 中形成精确像素规范。

### 继续保留

- 五卡顺序：`MILUKA → NAISHA → PEKO → YANQIU → BOMU`。
- `NAISHA / NYSHA` 英文拼写仍待最终核验，不得静默改写。
- 角色卡缩小并放在画面底部中央，不遮挡角色与美宣叙事。
- 左侧不放大信息板；文字和小图标直接排版。
- 三个特性不要一排排胶囊。
- `CONFIRM` 内只保留文字，不加左右装饰星。
- UI 必须适配五张冷暖不同的美宣，不为米露卡单独设计整套皮肤。
- 后续资产要方便抠图：正面视图、闭合轮廓、短阴影、动态文字与数值分离。

### “同行者星签”的新位置

“同行者星签”概念仍可保留，但不再要求整套 UI 都长成星形铭牌。它只负责底部五张角色入口：像旅行手册中的同行者标签，统一结构、少量角色色、选中态轻微上移。它是功能组件，不是整套世界观装饰的唯一载体。

## 九、本轮 UI 失败记录

### 1. 大白板／奶油板直接覆盖美宣

失败原因：遮断背景空间，把沉浸式角色选择页变成休闲儿童游戏或功能菜单。奶油色并非永远禁止，只禁止以大面板形式压在美宣上。

### 2. 深蓝星谱玻璃全页

失败原因：同色、平、缺少层级，所有按钮像一套蓝色玻璃胶囊。它不等于精致奇幻，只是统一换色。

### 3. 彩色圆润 2.5D 按钮路线

失败原因：仍然沿用“左侧信息板＋三条胶囊＋五张英雄卡＋右下大按钮”的通用手游骨架，只是换皮；无法解决模板感。

### 4. 深色强图形冒险 UI 参考

用户喜欢其统一切角、色彩编码、留白和设计系统，但它本身偏暗黑战斗／卡牌。可学习方法，不能直接使用黑底、荧光毒色和尖锐地牢语言。

### 5. “旅行星图册／同行者星签”铭牌资产板

文件：`assets/handoff/2026-08-28/ui-and-runner/ui-failure-travel-plaque.png`

失败原因：深蓝＋象牙白＋细金边、完全对称拱门、铆钉和衬线字共同把 UI 带成博物馆铭牌、酒店门牌或纪念牌；死板、暗淡、缺少旅行活力。

### 6. 轻量图形 UI 独立资产板

文件：`assets/handoff/2026-08-28/ui-and-runner/ui-failure-thin-wireframe-kit.png`

失败原因：提示词同时强调轻量、细边、平面、浅背景、方便抠图，并要求一次生成太多组件；模型把它平均成婚礼请柬／PPT 线框素材。星星只剩表面装饰，完全没有游戏视觉重量。

### 7. 资产板流程本身的失败

当前阶段先不要继续让生成模型在脱离页面语境的情况下同时设计全套资产。模型不知道实际视觉重量，只会把所有组件平均化。

新的流程是：

1. 用用户原型锁定页面布局与尺寸。
2. 用一张 UI 参考只锁图形规则与配色方法。
3. 先生成或手工构成完整页面概念图，只替换占位 UI，不改美宣。
4. 整页气质通过后，再反推单独组件和透明 PNG。
5. 最后进入九宫格、程序文字、数值和交互状态。

## 十二、加载动画状态

### 暂停未完成

加载动画的视觉核心仍是“英雄式卡通奇幻美宣外观＋风格化 3D 电影 CG 镜头”，不是真人写实，也不是简单推拉二维插画。

三段结构继续保留：

1. 甲虫段 6–7 秒：低机位穿草、落叶、叶片压弯回弹、米露卡平视探头。
2. 小队段 7–8 秒：佩可倒退逗奈纱、奈纱推回、砚秋无奈、波姆大笑、米露卡追队。
3. 世界段约 5 秒：悬崖揭示大陆，前景草叶或甲虫回到循环入口。

准确停点没有变化：星荚甲虫仍需最后一次局部微修——主要背对镜头、严格两根嫩芽触角、六条腿、窄折叠翅膜。通过后才能锁定甲虫、制作米露卡平视探头终帧并测试第一段视频。禁止恢复全图 Banana 精修。

跑酷主玩法使这段“同行旅途”加载动画更贴合项目，但不代表它已经完成，也不代表现在应当抢先恢复。

## 十四、回家后的执行顺序

### 当前唯一第一步：锁首版跑酷闭环

不要回家后立刻继续抽 UI，也不要先做 Logo 或甲虫。

先从一个问题开始：首版角色是自动向右前进，还是玩家可以控制左右移动？这个选择会决定关卡宽度、镜头、输入、HUD、角色能力和动画数量。

随后按顺序确认：

1. 基础移动与输入。
2. 一关的成功、失败和重试。
3. 岔路与收集的实际作用。
4. 五名角色首版如何产生差异。
5. 节奏小游戏放在营地、遗迹还是角色事件。
6. 首版只需要哪些页面。

### 第二步：建立最小 UI 系统

跑酷闭环确认后，再列首版页面：预计只保留营地／关卡地图／角色选择／关卡 HUD／结算／设置，实际以玩法讨论为准。

用《出发吧麦芬》参考学习奶油黄、浅蓝、暖橙、薄荷绿和“功能页完整面板／沉浸页边缘 UI”的双系统，不复制其商城、抽卡、活动与竖屏布局。

### 第三步：角色选择完整页面概念

- 以 `character-select-layout-prototype.png` 锁布局。
- 使用固定的温暖星路旅行 UI，不根据米露卡配色。
