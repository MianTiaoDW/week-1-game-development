# 2026-09-04 俯视角动作 Roguelite 最新玩法交接

> **当前玩法设计的最高优先级事实源。** 2026-08-28 的“关卡制横版冒险跑酷”已经被本轮决定取代。角色视觉、角色选择 UI、大厅 UI、Logo 和加载动画仍按各自专项交接继续，不因玩法转向自动改稿或恢复制作。

更新时间：2026-09-04（Asia/Shanghai）

## 1. 一句话方向

《星谱大陆》首版改为面向电脑网页的俯视角轻量动作 Roguelite：借鉴《元气骑士》清楚、短促的房间战斗循环，但不做纯枪械射击，也不复制其像素美术、角色、地图或完整系统。首个可玩版本只制作米露卡一名角色，验证“远程／近战即时切换＋闪避＋房间三波战斗＋战后三选一祝福”的核心乐趣。

## 2. 已确认的首版边界

### 平台与视角

- 目标平台：电脑网页。
- 视角：俯视角／斜俯视角房间战斗。
- 操作设备：首版以键盘和鼠标为准。
- 单局目标时长：约 5–8 分钟。
- 战斗密度：低到中等；少量敌人、清楚预警、强调走位与闪避，不做满屏弹幕。

### 本局结构

```text
大厅选择米露卡
→ 战斗房 1：三波敌人 → 中央宝箱三选一祝福
→ 战斗房 2：三波敌人 → 中央宝箱三选一祝福
→ 战斗房 3：三波敌人 → 中央宝箱三选一祝福
→ Boss 战
→ 完成本局或死亡结算
→ 返回大厅／重新挑战
```

- 每个普通战斗房共三波。
- 第一波：3 个基础敌人。
- 第二波：4–5 个混合敌人。
- 第三波：5–6 个敌人，其中包含 1 个精英敌人。
- 波次之间约停顿 1 秒，先显示清楚的出生提示，再生成敌人。
- 进入战斗后房门锁定；三波全部结束才解除封锁。
- Boss 房的具体 Boss、阶段和奖励尚未设计，不得自行补成定案。

### 中央宝箱与祝福

- 每个普通战斗房中央固定放置一个宝箱。
- 战斗期间宝箱封印，不可开启。
- 第三波清空后宝箱解除封印；玩家靠近后按 `F` 主动开启，不自动拾取。
- 开箱时暂停战斗，显示 3 张祝福卡，玩家用鼠标选择 1 张。
- 选择后立即生效，另外两张消失；首版没有刷新、保存或跳过。
- 祝福只在当前一局有效，死亡、重新挑战或完成本局后全部清空。
- 首版不做永久技能树和局外成长货币。

首批祝福池方向已确认，具体倍率仍待平衡：

1. 星光弹伤害提高。
2. 星光弹额外穿透 1 名敌人。
3. 扫帚横扫范围提高。
4. 扫帚横扫击退增强。
5. 切换攻击模式后的下一次攻击强化。
6. 闪避后短时间提高移动速度。

随机武器、装备掉落与大量道具暂缓。后期可以加入，但不能进入首个可玩版本，以免扩大美术、动作和数值制作量。

## 3. 米露卡首版操作与战斗套装

| 输入 | 动作 | 状态与反馈 |
|---|---|---|
| `WASD` | 八方向移动 | 角色朝移动方向运动；镜头和边界规则待原型确定 |
| 鼠标左键 | 使用当前攻击模式 | 远程或近战由 `Q` 的当前状态决定 |
| `Q` | 即时切换远程／近战 | 清楚显示当前模式；不打开菜单，不切换角色 |
| `E` | 星辉爆发 | 以米露卡为中心造成小范围伤害和击退，承担被包围时的解围功能；首版冷却 8 秒 |
| `Space` | 骑扫帚快速闪避 | 短距离位移并短暂无敌；首版冷却 1.2 秒 |
| `F` | 开启已解封宝箱 | 仅在靠近宝箱且房间战斗结束时生效 |

### 远程模式

- 鼠标左键触发，自动锁定合理范围内最近的敌人。
- 发射单枚星光弹。
- 重点反馈：清楚的发射节奏、弹道、命中闪光和轻微受击反应。
- 初始伤害、射速、射程与自动锁定规则仍需通过原型确定。

### 近战模式

- 鼠标左键触发，使用扫帚进行前方扇形横扫。
- 命中产生轻微击退，用于拉开距离和控制近身敌人。
- 重点反馈：前摇可读、横扫弧线干净、命中顿帧克制、敌人位移明确。
- 初始伤害、范围、攻击间隔与连击规则尚未锁定；首版优先单段攻击，不预设复杂连招。

### 主动技能与闪避

- `E` 星辉爆发同时服务两种攻击模式，不因切换而改变技能，减少首版制作量。
- `Space` 闪避用于躲避清楚的敌方攻击预警；无敌窗口必须短且可感知。
- 技能与闪避特效保持轮廓清楚、数量克制，兼顾网页性能和俯视角辨识。

## 4. 生命、受击与失败

- 米露卡初始生命为 6 点。
- 普通攻击命中扣 1 点生命。
- 精英或 Boss 的明确重击扣 2 点生命。
- 受击后提供 0.8 秒无敌保护，并有角色闪烁、轻微击退和声音反馈；后续仅在手感测试证明有问题时调整。
- 房间之间不自动回满生命。恢复生命以后可以作为祝福或战后奖励加入，但当前没有锁定具体来源。
- 生命归零时暂停游戏并显示两个操作：`重新挑战`、`返回大厅`。
- `重新挑战`：从本局第一间房重新开始，清空本局全部祝福。
- `返回大厅`：结束本局并回到大厅。
- 首版没有原地复活、当前房间续关或保留祝福重试。

## 5. 角色与队伍的后续方向

- 一局只操控一名角色，不做五人实时切换或同时跟随战斗。
- 首版只制作米露卡；其余四名角色继续保留在大厅／营地中。
- 未来每名角色都拥有自己独特的远程攻击、近战攻击和主动技能，但共享基础输入逻辑，允许玩家自由切换远程／近战模式。
- 未来可让其他角色以充能式伙伴援助出现，但当前不进入 MVP。
- 五名角色的身份、体型、脸、服装与道具仍以 `assets/character-masters/` 和 `docs/HANDOFF_2026-08-31_CHARACTER_TURNAROUNDS.md` 为准；玩法转向不授权静默增加武器或重做角色。

## 6. 首版明确不做

- 不做横版跑酷主循环。
- 不做五人组队实时战斗或战中换人。
- 不做随机武器、武器背包、装备词条和复杂道具系统。
- 不做永久技能树、局外数值养成和多货币经济。
- 不做满屏弹幕、大量同屏敌人和复杂连招。
- 不做多人联机、抽卡、商城、战令、公会或赛季系统。
- 不因参考《元气骑士》而复制其像素风、地图、敌人、武器或界面。

## 7. 尚待确认

以下内容仍是设计问题，不能写成已完成或已批准：

- 使用 Phaser、其他网页游戏框架，还是现有工程方案；需要先检查代码现状。
- 俯视角采用完全顶视还是轻微斜俯视，以及房间尺寸和镜头跟随方式。
- 米露卡各动作的精确伤害、射速、攻击范围、自动瞄准角度和冷却。
- 首批基础敌人、远程敌人、精英敌人的具体行为。
- Boss 的主题、招式、阶段、胜利奖励和失败反馈。
- 生命恢复是否进入首版祝福池。
- 完成本局后的结算画面和大厅反馈。
- HUD、祝福三选一界面、暂停界面和失败界面的最终视觉。

## 8. 回家后建议执行顺序

### 第一步：检查工程并锁技术方案

先确认仓库里是否已有可复用的网页游戏代码、框架和构建流程。若没有，优先评估 Phaser 的最小原型，不先制作完整 UI 或正式关卡资产。

验收目标：浏览器中能打开一个固定尺寸测试房间，米露卡占位体可用 `WASD` 移动，镜头和碰撞边界稳定。

### 第二步：只做米露卡战斗手感沙盒

依次接入远程星光弹、扫帚横扫、`Q` 切换、`E` 星辉爆发和 `Space` 闪避；先用占位图形验证输入与反馈。

验收目标：不依赖奖励、波次和 Boss，也能在一个房间里清楚感受到两种攻击模式的差异与切换价值。

### 第三步：接入一个最小敌人与受击闭环

先实现一种会接近玩家并进行清楚前摇攻击的基础敌人，再接入 6 点生命、扣血、受击保护、死亡菜单和整局重新挑战。

验收目标：玩家能躲、能受伤、能死亡，并可选择从第一间房重开或返回大厅。

### 第四步：完成三波房间与宝箱祝福

实现三波生成、门锁、出生提示、清场判断、中央宝箱、`F` 交互和三选一祝福。先使用 6 个已确认方向中的少量可验证祝福，不一次实现所有倍率组合。

验收目标：一个战斗房能从进入、三波战斗到选择祝福完整跑通，且不会提前开箱或提前开门。

### 第五步：复制为三房并加入 Boss 占位战

在单房闭环稳定后再串联三间战斗房和一间 Boss 房。Boss 初期可以使用占位行为验证整局长度，不先投入正式美术。

验收目标：一局在约 5–8 分钟内完成；死亡重开会清空祝福；三次祝福选择能够形成可感知的轻量构筑。

### 第六步：替换正式资产并做网页性能验证

核心循环通过后，再接入米露卡、敌人、场景、特效和 HUD 的正式资产，检查常用电脑网页视口下的帧率、输入、缩放、清晰度和音频反馈。
